# Results

Every number below is regenerated by `bash scripts/run_experiments.sh` (artefacts in
`docs/experiments/`). Corpus: 20 fictional *Meridian Bank* policy documents; evaluation set
`evalsets/policy_qa.jsonl`, 60 questions (54 answerable, 6 unanswerable, with `paraphrase`,
`multi-hop`, `numeric` and topic slices). Retrieval depth k = 5. Confidence intervals are
95 % bootstrap intervals over questions (1 000 resamples). Hardware for the model-backed
stages: one NVIDIA RTX 4070 (12 GB), Qwen2.5-1.5B-Instruct in bf16 via the in-process Hugging
Face backend, greedy decoding, used as **both** generator and judge.

## 1. Retrieval only (no model)

Gold-chunk metrics over the 54 answerable questions
([retrieval_bench_bge.md](experiments/retrieval_bench_bge.md),
[retrieval_bench_hash.md](experiments/retrieval_bench_hash.md)).

| Retriever | hit_rate@1 | hit_rate@5 | mrr | ndcg@5 | ms/query |
|---|---:|---:|---:|---:|---:|
| BM25 (from the Okapi formula) | 0.852 [0.76, 0.94] | 1.000 | 0.911 | 0.934 | 0.1 |
| Dense, hashing embedder (no model) | 0.759 [0.65, 0.87] | 0.889 | 0.809 | 0.827 | 0.1 |
| Dense, bge-small-en-v1.5 | 0.889 [0.81, 0.96] | 0.981 | 0.932 | 0.945 | 16.1 |
| Hybrid RRF (BM25 + bge-small) | 0.926 [0.85, 0.98] | 1.000 | 0.963 | 0.973 | 15.8 |
| Hybrid convex (BM25 + bge-small) | 0.926 [0.85, 0.98] | 1.000 | 0.960 | 0.970 | 17.3 |
| **Hybrid RRF + cross-encoder rerank** | **1.000** | 1.000 | 1.000 | 1.000 | 189.5 |

What the table says:

- A hashing embedder is not a retriever: fused with BM25 it *lowers* hit_rate@1 (0.852 →
  0.815). Fusion only helps when the dense leg is genuinely good.
- With bge-small the dense leg beats BM25 on its own (0.889 vs 0.852) and RRF fusion beats
  both (0.926). The gain is concentrated in the `paraphrase` slice, where the question avoids
  the document's vocabulary — the case BM25 cannot handle by construction.
- The MiniLM cross-encoder fixes every remaining rank-1 miss at ~12× the latency of the hybrid
  retriever (189 ms vs 16 ms per query on CPU) — the usual retrieve-cheap-then-rerank trade.

## 3. Paired comparison: does better retrieval make better answers?

`ragpipe compare` pairs the two runs question by question (paired bootstrap on the
per-question difference; "better" requires the interval to exclude zero, "non-inferior"
requires it to stay inside the margin) —
[compare_hybrid_vs_bm25.md](experiments/compare_hybrid_vs_bm25.md).

| Metric | n | Hybrid + rerank | BM25 | Δ | 95 % CI | P(Δ > 0) | Verdict |
|---|---:|---:|---:|---:|:---:|---:|---|
| context_precision | 54 | 0.975 | 0.884 | +0.091 | [+0.038, +0.156] | 1.00 | **better** |
| retrieval/mrr | 54 | 1.000 | 0.911 | +0.089 | [+0.034, +0.147] | 1.00 | **better** |
| retrieval/recall@5 | 54 | 1.000 | 1.000 | 0.000 | [0.000, 0.000] | – | non-inferior |
| false_abstention | 54 | 0.019 | 0.019 | 0.000 | [0.000, 0.000] | – | non-inferior |
| faithfulness | 53 | 0.897 | 0.903 | −0.006 | [−0.057, +0.050] | 0.37 | inconclusive |
| answer_relevancy | 54 | 0.694 | 0.689 | +0.005 | [−0.038, +0.045] | 0.57 | inconclusive |
| context_recall | 54 | 0.867 | 0.863 | +0.005 | [−0.065, +0.074] | 0.54 | inconclusive |
| lexical/reference_coverage | 54 | 0.649 | 0.666 | −0.017 | [−0.072, +0.038] | 0.29 | inconclusive |
| correct_abstention | 6 | 0.667 | 0.833 | −0.167 | [−0.500, 0.000] | 0.00 | inconclusive |

The honest reading: the reranked hybrid retriever is *measurably* better at retrieval
(rank-1 hit rate 0.852 → 1.000, context precision +0.09 with an interval that excludes zero),
but with a 1.5 B generator that gain **does not reach the answer**. Faithfulness, answer
relevancy and context recall are all within noise of the BM25 baseline. On this corpus the
gold chunk was already in the top 5 for every question under BM25 (recall@5 = 1.000), so the
generator, not the retriever, is the bottleneck. A point-estimate comparison would have
reported the hybrid pipeline as "worse on faithfulness" (0.885 vs 0.903); the paired interval
says that difference is not real.

## 4. Production gate

`ragpipe gate --gates gates/production.yaml` on the hybrid + rerank run
([gate_hybrid_rerank.md](experiments/gate_hybrid_rerank.md)). Faithfulness is tested on the
**lower bound** of its interval (`use_ci: true`), which is what a release decision should use.

| Gate | Threshold | Observed | Result |
|---|---|---:|:---:|
| faithfulness (CI lower bound) | ≥ 0.85 | 0.819 (mean 0.885) | FAIL |
| answer_relevancy | ≥ 0.70 | 0.694 | FAIL |
| context_recall | ≥ 0.80 | 0.867 | PASS |
| retrieval/recall@5 | ≥ 0.85 | 1.000 | PASS |
| false_abstention | ≤ 0.10 | 0.019 | PASS |
| correct_abstention | ≥ 0.80 | 0.667 | FAIL |

**Decision: HOLD.** This is the intended outcome, not a bug. The retrieval side clears every
gate; the generation side does not — a 1.5 B model grounded in bank-policy text is faithful
about 89 % of the time, and the gate is set at 85 % on the conservative bound. The exit code
of the command is the decision, so the same file blocks a CI promotion.

## 5. Abstention on the unanswerable questions

Six questions have no answer in the corpus. The model is instructed to say so; the metrics
count both directions of error.

| | BM25 only | Hybrid + rerank |
|---|---:|---:|
| Correct abstentions (of 6) | 5 | 4 |
| False abstentions on answerable questions (of 54) | 1 | 1 |

With the reranker the retrieved context looks *more* relevant to every question, including
the unanswerable ones, and the model answers one more of them. Better retrieval makes an
unanswerable question look answerable — a failure mode the abstention gate exists to catch.

## 6. Where faithfulness fails

The lowest-scoring answers are the same in both runs (`## Lowest faithfulness` in each
report): numeric questions where the model states a figure that is *near* the context but not
in it (an LCR trigger and target quoted as the same number, a review cadence stated without
support), and multi-condition questions where one clause is invented. These are the classic
small-model grounding errors; the judge caught them, and they are what pulls the lower bound
of faithfulness under the gate.

## 7. Cross-check against the official `ragas` implementation — open

`ragpipe ragas-crosscheck` runs the official `ragas` package (0.4.x) over the same answers and
reports per-metric mean absolute difference and rank correlation. On this machine the run
failed inside the library's Hugging Face embedding wrapper (`Cannot copy out of meta tensor;
no data` on model load, a transformers 5.x incompatibility; log kept in
`runs/ragas_crosscheck.log`), so **no agreement numbers are reported here**. What stands
instead: each metric is unit-tested against hand-computed cases from the published
definitions, and every judge verdict is parsed with id-aligned statements and
missing-not-zero semantics. Re-running the cross-check with a compatible `ragas` release is the
remaining item.

## 8. What this project demonstrates

- Retrieval quality is easy to improve and easy to measure; answer quality is bounded by the
  generator, and only a **paired** comparison shows that honestly.
- A gate on the confidence interval's conservative bound holds a configuration that a
  mean-based gate would have promoted (mean faithfulness 0.885 ≥ 0.85, bound 0.819 < 0.85).
- Abstention has to be measured in both directions, and better retrieval can make it worse.
- Every judge call either produces a parsed verdict or a *missing* value — never a silent
  zero — and the missing counts are reported next to each metric.
